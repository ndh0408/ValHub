## 0. Summary

1. **Tool**: official Flutter `gen-l10n`. ARB files in `lib/l10n/arb/`, `app_vi.arb` is the template, 17 more locale files, generated Dart committed in `lib/l10n/gen/`. No new runtime dependency (`flutter_localizations` and `intl ^0.20.3` are already in `pubspec.yaml`).
2. **Access**: widgets read `context.l10n.<key>`; providers `ref.watch(l10nProvider)`; the background isolate reads `BackgroundContext.l10n`. There is no global "current language" accessor anywhere. Numbers/dates/relative time go through `context.fmt` (`AppFormats`).
3. **Layering rule**: "keys, not text, below the view". Domain, content models, enums, exceptions and isolates return enums/ids/codes/data; text is produced at the view boundary by extension methods on `AppLocalizations`. This is what makes the migration tractable (cuts 784 edit sites to about 360) and is what keeps `ContentDb.parse` (runs in `Isolate.run`) and notifications correct after a language switch.
4. **Migration** is done by a deterministic, re-runnable, analyzer-based codemod (`tool/l10n_codemod/`, own pubspec, analyzer pinned to 10.2.0). 80% of call sites are mechanical, 20% (310 refs, 113 symbols) are structural and are handled by human/agent work packages that own disjoint file sets. The old `*Strings` classes keep compiling until the final cutover, so every merge is analyze-clean and test-green.
5. **No user-visible change until cutover.** A `kShippedLocales` set starts as `{vi}`; locale resolution and the picker only ever return shipped locales. Everything merges continuously to the main branch. There is no long-lived i18n branch.
6. **Translation**: Vietnamese to English first (owner-reviewed pivot and runtime fallback), then 16 more locales by a Claude-driven runner with glossary, JSON-schema output, deterministic validators, back-translation sampling and per-locale status files. A missing key is filled from English (never from Vietnamese) and CI gates on it.
7. **Effort**: about 45-60 agent-hours for the vi-identical cutover (W0-W4), 90-125 agent-hours for all 18 languages including RTL/font QA. Wall clock 4-7 days with 4-8 parallel agents (section 18).

Three designs were evaluated by two judges.

| Design | Judge 1 | Judge 2 | Sum | Verdict |
|---|---|---|---|---|
| P1: gen-l10n + `context.l10n` + layering rule + analyzer codemod | 37 | 33 | **70** | **Chosen base** |

**Why P1 wins despite the highest churn.** (a) Widget text cannot go stale: `Localizations` is an `InheritedWidget`, so a language switch rebuilds dependents with no sweep and no global. P2 and P3 need a rebuild hack (`rebuildAllElements` / `LocaleRebuildScope`) and prove correctness by a detector test instead of by construction. (b) It is the only design that handles `ContentDb` correctly: the `ContentDb` constructor bakes `ContentFallbacks.currencies/contentTiers` (`lib/core/content/content_db.dart` lines 148-153) and `ContentDb.parse` runs in `Isolate.run` (`content_repository.dart` line 88-94), a fresh isolate with no static state. A global accessor would bake the wrong language into a long-lived object. (c) First-party tooling, ARB is what every translation management system speaks, generated code is plain `switch`/string (no runtime ICU parse). (d) Its cost, the 310 no-context references, is finite, enumerated and parallelisable.

## 3. Architecture

### 3.1 Principles

1. One source of truth for text: `lib/l10n/arb/app_vi.arb` (template). Nothing else is edited by hand except metadata in it.
2. No mutable global language. Every consumer gets its `AppLocalizations`/`AppFormats` from `Localizations`, a provider, or the background composition root.
3. Below the view layer nothing returns translated text (section 3.3).
4. vi output must stay byte-identical through the cutover (parity test, section 12.4), then improve deliberately.
5. Nothing non-editorial goes through translation: country names (CLDR), language autonyms (const), weekdays/months (intl), content names (valorant-api), legal documents (assets).
6. Every wave is analyze-clean and test-green; every merge is user-invisible until a locale is in `kShippedLocales`.

### 3.2 Access tiers

| Tier | Where | Access |
|---|---|---|
| Widgets | anything with a `BuildContext` | `context.l10n.<key>` (extension, throws a clear `FlutterError` if the delegate is missing); `context.fmt` for formats. Do NOT name any accessor `t`: 53 local identifiers named `t` exist in 26 files that reference strings. |
| Riverpod providers/notifiers | no context | `ref.watch(l10nProvider)` / `ref.watch(formatsProvider)` (never `ref.read`, so they rebuild on language change) |
| Background isolate composition root | WorkManager task, no widgets | `BackgroundContext.l10n` / `.formats`, built with `lookupAppLocalizations(locale)` from the persisted effective locale (section 10) |
| Tests | anywhere | `tl` from `test/helpers/l10n.dart` (locale from `TEST_LOCALE`, default `vi`) |

Forbidden: a static `AppLocalizations.current`, any `static final`/`late final`/top-level `final` initialised from `l10n`, storing translated strings in `Notifier` state.

### 3.3 Layering rule and the six patterns

Rule: **domain, content models, enums, exceptions, providers' state and isolates return keys/enums/data. Text is resolved at the view boundary.** Six patterns cover all 310 no-context refs:

**P-A enum labels -> extension on `AppLocalizations`.** 14 enum getters plus 4 enums with const-constructor strings (`WeaponCategory` x7, `NotificationChannel` x8, `SkinSort` x4, `CollectionBrowseType` x6). The enum keeps its id and loses text and any l10n import; the dependency arrow points from `labels/` to `domain`.
```dart
// lib/core/domain/competitive/match_models.dart
enum MatchOutcome { win, loss, draw }          // was: String get label => switch (this) {... CompetitiveStrings.victory ...}
// lib/core/l10n/labels/competitive_labels.dart   (owned by the domain work package)
extension CompetitiveL10n on AppLocalizations {
  String matchOutcome(MatchOutcome o) => switch (o) {
    MatchOutcome.win => competitiveVictory,
    MatchOutcome.loss => competitiveDefeat,
    MatchOutcome.draw => competitiveDraw,
  };
}
// call site: outcome.label  ->  context.l10n.matchOutcome(outcome)
```
**P-B pure describing/format functions get a leading `AppLocalizations l10n` parameter**: `describeError`, `describeCommunityError`, `presenceStatus`, `currentGameStatusText`, `queueBlockReason`, `joinErrorMessage`, `lfgRoleLabel`, `rankRangeLabel`, `languageFilterLabel`, `formatActEnd`, and everything in `format.dart` (which becomes `AppFormats`, section 7). Call sites pass `context.l10n` (or the provider value).

**P-C model getters that bake labels become keyed data + a label extension**: `Currency.label/fullLabel`, `ContentTier.shortName`, `PlayerTitle.text`, `SkinLevel.levelItemLabel`, `AgentRole.label`, `CompetitiveTier.displayName`, `ContentDb.item` `typeLabel`, `ContentFallbacks.currencies/contentTiers/queueNames/...`. `ContentDb.parse` and the `ContentDb` constructor become locale-neutral (no `ContentFallbacks` text is baked; fallback entries carry ids only). Labels resolve through `content_labels.dart`, whose policy is: use the valorant-api text when the content language equals the UI language and the UI language is not `vi`; otherwise use the ARB text (vi keeps app-owned overrides because the API's Vietnamese names are re-cased English).

**P-D exceptions with baked text keep codes.** `MaxAccountsException`, `LoadoutSaveException`, `CommunityException`: expose a code enum + `serverMessage`; the UI maps codes with `describeXError(l10n, e)`. The `message` getters are removed.

**P-E background/notification code reads `BackgroundContext.l10n`.** `NotificationChannel` becomes `id` + `String Function(AppLocalizations)` name/description; scheduled-in-advance texts (store reset reminder) are rebuilt on locale change (section 10).

**P-F widget const defaults and static const label lists.** The 13 constructor default values (`adaptive.dart`, `async_value_view.dart`, `empty_view.dart` x2, `filter_bar.dart`, `report_sheet.dart`, `community_widgets.dart` x2, `live_roster.dart`, `match_history_sliver.dart`, `collection_widgets.dart`, `store_ui_bits.dart`, `scope_bar.dart`) use the private-named-parameter pattern (Dart 3.12+, repo is ^3.13.4) so the public parameter name is unchanged and the constructor stays `const`:

```dart
  final String? _actionLabel;
  String actionLabel(BuildContext c) => _actionLabel ?? c.l10n.commonRetry;   // resolved in build
```
`AppShell._destinations` (6), `AboutScreen._features` (10), welcome bullets become methods taking the `AppLocalizations`; `legalNotice` becomes a loaded asset (section 11.2).

## 4. Message modeling (ARB)

### 4.1 Keys, sections, ownership

Key = `lowerCamel(classPrefix + Member)`. Prefix table (exact): `common content account auth notification competitive economy loadout battlePass collection community liveGame profile legal settings skinDetail social store wishlist home`. (`home` is the 20th: `HomeStrings` appeared with the Home tab after this document's measurement; it is appended so the other 19 keep their order. The order lives in `tool/l10n_fmt.dart` `kKeyPrefixOrder` and `tool/l10n_codemod/lib/src/known_classes.dart`; a test keeps them equal and fails when a new `*Strings` class is added without an entry.) Examples: `CommonStrings.retry` -> `commonRetry`, `BattlePassStrings.levelOf` -> `battlePassLevelOf`, `SkinDetailStrings.x` -> `skinDetailX`. Measured: 0 collisions among 1,264 members. 75 groups of duplicate Vietnamese text across classes are reported (`reports/duplicates.md`) and NOT merged: translations are context dependent.

`app_vi.arb` is one flat file grouped by prefix in the fixed order above; `tool/l10n_fmt.dart` (idempotent) sorts keys by (prefix order, extraction order) and normalises JSON layout. A work package edits only keys of the namespaces it owns, so git merges stay clean (G6). The 17 other files are written only by tools.

### 4.2 Entry anatomy

```json
"commonMinutesAgo": "{n, plural, other{{n} phút trước}}",
"@commonMinutesAgo": {
  "description": "Relative time, minutes. Shown on match rows and 'updated' labels.",
  "placeholders": { "n": { "type": "int" } },
  "x-example": "5 phút trước",
  "x-context": "common/relative-time",
  "x-max-length": 24
},
"commonVp": "VP",
"@commonVp": { "description": "Valorant Points currency symbol", "x-locked": true }
```
`x-*` attributes are ignored by gen-l10n and consumed by tools: `x-example` (rendered vi output, e.g. `Cấp 46 / 55`), `x-context` (screen/section), `x-max-length` (budget from the vi text, section 14.6), `x-locked` (copied verbatim to every locale, never sent to a model), `x-caps` (see 4.5), `x-tags` (allowed inline tags). Placeholders are declared in the ORIGINAL parameter order because gen-l10n emits positional parameters in the `placeholders` map order (verified), so call-site arguments stay byte-identical. Count placeholders have no `format` in the vi template (parity: old code printed `$n`); adding `decimalPattern` for counts that can exceed 999 is a deliberate post-parity change listed in the W5 tasks.

### 4.3 Member kind to ARB form

| Old member | New form |
|---|---|
| `static const x = 'text'` | plain message |
| `static String f(String a, int n) => 'text $a $n'` | ICU with typed placeholders |
| int `n` followed by a noun, or ternary on `n == 0/1` | `{n, plural, other{...}}` in vi (translators add `one/few/many/zero/two`); `=0`/`=1` kept when the old code branched |
| pre-formatted `String` count (about 12) | signature changes to `int`; format inside the message |
| nullable params, `Iterable` joins, `bool` switches, `switch` | full-sentence messages + a thin hand-written wrapper in `labels/<ns>_labels.dart` that selects between them. ARB never branches on nullability. e.g. `SocialL10n.inMatchStatus(String? map, {int? ally, int? enemy})` selects `socialInMatch` / `socialInMatchOn(map)` / `socialInMatchOnScore(map, ally, enemy)`. `bool` -> two messages (`wishlistTileSemantics`). |
| `SocialStrings.sentence` + `reason*` fragments capitalised on demand | full sentences, both forms; no runtime string surgery |
| `regionLabel` | `{r, select, ... other{...}}` |
| joins (`dotJoin`, `joinParts`, `joined`) | natural-language lists use `commonListSeparator` (`', '`; ja/zh `'、'`; ar `'، '`); middle-dot fact separators (`'a · b'`) stay a Dart constant |
| const map/list (`queueNames`, `roleNames`, `levelItemLabels`, `slotNames`, `ratingWords`, `reportReasons`, `otherGames`) | one key per entry (`contentQueueNamesCompetitive`) + generated lookup `contentQueueName(l10n, id)` in `labels/content_tables.g.dart` |
| alias (`CollectionStrings.noTitle = ContentStrings.noTitle`) | dropped; call sites repointed to the original key (G14) |
| dead (97) | skipped, reported for deletion |
| not editorial: `weekdays`, `countryNames` (114), `languageNames` (17) | removed from ARB: `DateFormat.EEEE` (verified identical vi output), CLDR territory assets, `AppLocale.nativeName` |

Neutral tokens (VP, KC, RP, PC, RR, K/D/A, ACS, HS%, ADR, MVP, PlayStation, Xbox, ValVN, Battle Pass, dashes, approx sign, slash/colon structure) get `x-locked: true`; `l10n_sync` copies them into every locale (G14).

| `extract [--update-new\|--adopt]` | build/refresh `app_vi.arb`, `manifest.json`, `reports/*` from the 19 classes. `--adopt` appends members added to old classes after W1 (used only during the freeze window; the freeze test tells authors to run it). |

Guarantees: same input tree + same tool version = same output (byte-stable: ordered keys, fixed indent, no timestamps; header carries only the input git SHA); a second run is a no-op; `--dry-run` prints a unified diff; every write phase ends with `dart analyze` on touched files and aborts on NEW diagnostics; edits are `SourceEdit`s from element resolution (never regex) applied right-to-left per file, followed by `dart format` on changed files.

```text
      switch classify(m):
        STRING:   arb[key] = text                                       // SimpleStringLiteral / AdjacentStrings without interpolation
        ICU:      arb[key] = toIcu(body, params, siblings)             // StringInterpolation with only param identifiers; sibling const/fn interpolation inlined (30 intra-class refs)
        PLURAL:   int param followed by a word  -> {n, plural, other{..}}; ternary n==0/1 -> =0/=1 forms; flag for review
        COUNT_STRING: param is a pre-formatted String count -> manifest.signatureChange = int; flag
        ALIAS:    manifest[m] = alias(target)                           // no ARB entry
        MAP/LIST: expand one key per entry + contentLookup table in content_tables.g.dart
        NEUTRAL:  message has no letters after removing placeholders, or is a glossary token -> x-locked
        HAND:     report.hand << m                                      // NEVER guessed; supplied via overrides
      meta = {description: docComment + nearest section comment, placeholders (type from Dart param, order kept),
              x-example: from doc-comment sample or rendered, x-context, x-max-length: budget(vi text), x-caps if all upper}
  write app_vi.arb (sorted), manifest.json, reports/{hand_conversions,dead,duplicates,tearoffs,case_transforms,list_map_uses}.md
```
`manifest.json` entry examples:
```json
"CommonStrings.retry":       {"key":"commonRetry","kind":"string"},
"CommonStrings.minutesAgo":  {"key":"commonMinutesAgo","kind":"plural","params":[["n","int"]]},
"SocialStrings.inMatch":     {"kind":"wrapper","rewrite":"{l10n}.socialInMatchStatus({args})","keys":["socialInMatch","socialInMatchOn","socialInMatchOnScore"]},
"ContentStrings.queueNames": {"kind":"map","rewrite":"contentQueueName({l10n}, {index})"},
"CollectionStrings.noTitle": {"kind":"alias","to":"ContentStrings.noTitle"},
"AccountStrings.regionX":    {"kind":"dead"}
```
`overrides/<class>.json` holds, per hand member, the messages (vi text, placeholders) and the wrapper signature; the wrapper source itself is written by the W1 agent into `lib/core/l10n/labels/<ns>_labels.dart`.

### 5.3 Rewrite rules

| Rule | Transformation |
|---|---|
| R1 | `Cls.member` -> `<l10n>.<key>` where `<l10n>` = innermost usable named `BuildContext` parameter as `ctx.l10n`, else `context.l10n` in a non-static `State` member, else hoisted local `l10n` (R4), else `tl` under `test/` (import `test/helpers/l10n.dart`), else **leave and record** in `todo_noctx.json` `{file,line,symbol,pattern,enclosing}`. | R2 | Const removal: walk up from the ref, find the outermost enclosing const context root (`const` `InstanceCreationExpression`, `const` list/set/map literal, `DefaultFormalParameter`, const variable, enum constructor argument) and delete only its `const` keyword. Field/variable declarations and default parameters are NOT edited by the tool; they are added to `todo_noctx.json` with pattern P-F. |
| R2b | Const restore: run `dart analyze --options tool/l10n_codemod/const_overlay.yaml --format=machine <touched files>` where the overlay enables `prefer_const_constructors` and `prefer_const_literals_to_create_immutables`; for each diagnostic inside a region recorded by R2 insert `const`; loop until stable (max 5 rounds). See `tool/l10n_codemod/const_overlay.yaml`. |
| R3 | Calls `Cls.fn(args)` -> `l10n.key(args)` (arguments untouched); tear-off `Cls.fn` -> `l10n.key` (instance-method tear-off, valid for `String Function(String)`); wrapper/map/list kinds use the manifest `rewrite` template. |

## 6. Locale resolution, persistence and switching

### 6.1 Resolution

```dart
AppLocale resolve(List<Locale> device, {Set<AppLocale> shipped = kShippedLocales}) {
  for (final l in device) {                       // device preference order
    final m = _match(l);
    if (m != null && shipped.contains(m)) return m;
  }
  return shipped.contains(AppLocale.en) ? AppLocale.en : AppLocale.vi;   // product is global: fallback is English, not Vietnamese
}
AppLocale? _match(Locale l) {
  final lang = switch (l.languageCode.toLowerCase()) { 'in' => 'id', final c => c };   // legacy Android code
  final country = l.countryCode?.toUpperCase(), script = l.scriptCode;
  switch (lang) {
    case 'zh': return (script == 'Hant' || const {'TW','HK','MO'}.contains(country)) ? AppLocale.zhHant : AppLocale.zh;
    case 'es': return (country == null || country == 'ES') ? AppLocale.es : AppLocale.esMx;   // es-419, es-US, es-MX, es-AR ... -> esMx
    case 'pt': return AppLocale.pt;               // pt-PT too: VALORANT only offers pt-BR
    case 'ar': return AppLocale.ar;
    default:   return AppLocale.values.where((v) => !v.isPseudo && v.flutter.languageCode == lang).firstOrNull;
  }
}
```
`nb`, `no`, `hi`, ... match nothing and continue down the device list, ending at `en`. Unit-tested table: `zh-Hant-TW`, `zh-TW`, `zh-HK`, `zh-Hans-CN`, `zh-SG`, `es-419`, `es-ES`, `es`, `es-US`, `in`, `nb`, `pt-PT`, `pt-BR`, `ar-EG`, `fr-CA`, `de-AT`, `en-GB`, plus multi-locale lists (`[hi, ja]` -> `ja`; `[hi]` -> `en`) and the `shipped` filter (`{vi}` only -> always `vi`).

### 6.2 Persistence keys (`PrefKeys`, conventions `settings.*`)

| Key | Values | Meaning |
|---|---|---|
| `settings.appLocale` | `"system"` or an `AppLocale.tag` | UI language choice. Absent = undecided (see 6.4). |
| `settings.contentLocale` | `"app"` or a tag | item-name (valorant-api) language; replaces `ItemLanguage {vi,en}` |
| `settings.effectiveLocale` | JSON `{"v":1,"app":"de-DE","format":"de_AT","h24":true,"content":"de-DE"}` | written by the UI isolate on every change; read by background isolates (10) |

### 6.3 Runtime objects

`deviceLocalesProvider` reads `WidgetsBinding.instance.platformDispatcher.locales` (NOT `PlatformDispatcher.instance`, so the test binding's `localesTestValue` applies) and updates from `WidgetsBindingObserver.didChangeLocales`. `appLocaleProvider` = choice (`system` -> `resolve(device)`; a tag -> that locale if shipped else `resolve`). `formatTagProvider` = the intl tag: the app locale's `intl tag`, except that when the device's first locale has the same language as the app locale and `intl` has data for `lang_COUNTRY` (e.g. `en_GB`, `de_AT`, `es_AR`) that regional tag is used so dates/numbers follow the user's region. `use24hProvider` = `MediaQuery.alwaysUse24HourFormat` mirrored (vi always 24 h).

**As built in W0** (`locale_boot.dart` `resolveFormatTag`, `locale_controller.dart`):
- "Same language" is stricter: the device's first locale must map to the app locale ITSELF (`AppLocale.fromLocale(first) == app`), so a manual Simplified-Chinese choice on a `zh_TW` phone stays `zh_CN` and a Spain-Spanish choice on a Mexican phone stays `es`. `AppLocale.regionalFormats` is false for `ar` (`ar_EG` would print Arabic-Indic digits). The whole rule is on by default (decision 10 in 18.3) behind the `regional` parameter. Measured in `intl 0.20.3`: `en_GB en_AU de_AT de_CH es_419 es_US pt_PT zh_HK fr_CA` exist; `vi_VN es_AR zh_SG en_001 de_DE ...` do not (so a `vi_VN` phone gives the tag `vi`: Vietnamese stays byte-identical).
- `use24hProvider` is the raw device setting, read from `WidgetsBinding.instance.platformDispatcher.alwaysUse24HourFormat` and refreshed on the same platform callbacks `MediaQuery` uses (there is no dedicated observer method); "Vietnamese is always 24 h" is applied inside `AppFormats.time`.
- `l10nBootProvider` defaults to `L10nBoot.system(device)`, which persists nothing; `main()` overrides it with `L10nBootstrap.load`. As of the runtime checkpoint, `ValVnApp` reads `appLocaleProvider` and wraps the router app in `AppFormatsScope`. Only `kShippedLocales` is exposed (currently vi).
- `settings.effectiveLocale` has its reader/writer (`EffectiveLocale`, JSON v1, parsed defensively) and `effectiveLocaleProvider`. The root now writes initial/changed snapshots sequentially with error recovery, retaining the existing independent item-name preference. Background consumption and notification localization still require W5 work; do not infer those from the presence of the snapshot.

### 6.5 Language switch procedure (`LocaleController.set(choice)`)

1. Persist `settings.appLocale`; recompute `AppLocale` and the format tag. 2. State update rebuilds `MaterialApp` (new `locale`), `Localizations` reloads synchronously (both `AppLocalizations` and `material_ui` delegates return `SynchronousFuture`, no flash), `Intl.defaultLocale` is updated. 3. Re-run the store-reset reminder scheduling for the active account. 7. ## 7. Formatting per locale

`lib/core/l10n/formats.dart` replaces the locale-dependent half of `core/util/format.dart`. `AppFormats(AppLocale locale, AppLocalizations l10n, String tag, bool h24)` is a pure Dart object (no `dart:ui`), so it also works in the background isolate. Access: `context.fmt` (looks up an `AppFormatsScope` inherited widget above `MaterialApp`; falls back to `Localizations.localeOf` + `MediaQuery.alwaysUse24HourFormatOf` so bare test harnesses work; both register dependencies so widgets rebuild on change), `ref.watch(formatsProvider)`, `ctx.formats`.

| Method | Behaviour |
|---|---|
| `number`, `compact`, `signed`, `percent(fraction, decimals)` | `NumberFormat.decimalPattern/compact/decimalPercentPattern(tag)`; non-finite -> `0` |
| `vp`, `kc`, `rp`, `currency(amount, iso)`, `estimatedPrice` | number + unit suffix after the number; currency via `NumberFormat.simpleCurrency`; wrapped in `bidi()` for RTL |
| `date`, `dayMonth`, `time`, `dateTime`, `weekday`, `weekdayShort` | `DateFormat` skeletons for the tag; `weekday` = `DateFormat.EEEE` (drops `CommonStrings.weekdays`); `time` = `Hm` when `h24` or the locale's `jm` has no day-period, else `jm` |
| `relative`, `countdown`, `durationCoarse`, `dayHeader`, `updatedAt`, `wallTime` | use ARB plural messages (`commonMinutesAgo`, `commonDays`, ...) plus clock digits; take `now` explicitly (`clockProvider`) |
| `upper`, `lower`, `titleCase` | locale-aware (tr/az `i`/`I`/`İ`/`ı`); `titleCase` replaces `viTitleCase` and is a no-op for uncased scripts |
| `bidi(String)` | wraps scores (`8 - 4`), timers, `Name#TAG` Riot IDs and amounts in LRI/PDI isolates when the app is RTL |
| `sortKey(String)`, `listJoin(Iterable<String>)` | fold key from `search_text.dart` (raw name as tie-breaker), `commonListSeparator` |

Rules: **vi stays byte-identical** (goldens, 59 test refs): `date` = `dd/MM/y`, `time` = `HH:mm`, percent comma decimals, weekday names from intl (verified equal to today's list). All other locales use CLDR patterns by design. `ar` uses `intl` tag `ar` (Latin digits); `ar_EG` would switch to Arabic-Indic digits, so it is never used. Thai prints Gregorian years (owner may reverse). `zh_Hant` maps to `zh_TW` data. Free helpers that run in `fromJson` and are locale-independent (`cleanDisplayText`, `isRawLocKey`, `firstLine`, `restLines`) stay in `core/util/format.dart`. The old free functions stay as deprecated shims until W4 and are then deleted (`currentIntlLocale()` too).

Search and sort: `lib/core/util/search_text.dart` (already language-independent) is the single fold; remaining `vi_search.dart` / `collection_search.dart` wrappers and `foldVietnamese` in `core/xmpp/friends.dart` delegate to it and are deleted. The 8 name-sort sites (`content_db`, `owned_items`, `top_skins_section`, `live_game_logic`, `match_filter`, `skin_query` x2, ...) sort by `fmt.sortKey`. Dart has no locale collation; for ja/zh/ko/th/ar order is by fold key/code unit, which is acceptable because every list also has search (documented limitation).

## 8. RTL, scripts, fonts, accessibility, layout

### 8.1 RTL

Directionality flips for `ar` via `GlobalWidgetsLocalizations`. Backlog (section 2.5, about 400 sites, W7): `rtl` codemod rules, each site reviewed:
- asymmetric `EdgeInsets.fromLTRB(a,b,c,d)` with `a != c` -> `EdgeInsetsDirectional.fromSTEB`; `EdgeInsets.only(left/right)` -> `EdgeInsetsDirectional.only(start/end)`. Symmetric insets are left alone.
- `Alignment.centerLeft/topRight/...` -> `AlignmentDirectional.centerStart/topEnd/...`.
- `Positioned(left:/right:)` -> `PositionedDirectional(start:/end:)` unless the element is physical art, a chart or a video control.
- 21 directional icons (chevrons, back/forward arrows): `core/ui/dir_icons.dart` `context.dirIcon(forward: Icons.chevron_right, back: Icons.chevron_left)` picks by `Directionality`.
- `fl_chart` charts, physical-left artwork and video controls are wrapped in `Directionality(textDirection: TextDirection.ltr)` and are not mirrored.
- Scores, timers, RR/VP amounts, `Name#TAG` go through `fmt.bidi`; pure numeric `Text` sets `textDirection: TextDirection.ltr`.
Tests: direction smoke per screen group under `ar` and `ar_XB` (12.3).

### 8.2 Fonts and scripts

Theme (`lib/core/theme/app_theme.dart`): Latin/Vietnamese keep Be Vietnam Pro/Anton. For ru, th, ar, ja, ko, zh, zhHant the theme sets `fontFamilyFallback` for the platform's Noto/system families, drops Anton for localized titles (`TabPageScaffold`, map names; rank digits keep Anton because digits are Latin), letter-spacing 0, and uses `material_ui`'s per-script `Typography` (tall/dense line heights). `Text` selects the Han variant from `Localizations` automatically (ja vs zh-CN vs zh-TW). Bundling Noto subsets (CJK is MBs) is an owner decision (18.3); the default is system fallback with an on-device acceptance check in ja/ar/th/ru (W7). Be Vietnam Pro lacks the sort arrows: replace with icons.

### 8.3 Text expansion, large text, small screens, tablets

`x-max-length` budgets (14.6) plus overflow tests at 360 dp and text scale 2.0 in de, ru, ar, ja, th (12.3). The 219 existing `maxLines`/ellipsis sites are the safety net, not the design. No fixed-height containers around text. Tablet/iPad/foldable/landscape are handled by the adaptive-layout work (`core/ui/adaptive.dart`); this design supplies i18n hooks only (semantic labels as ARB keys, country names, `AppLocale` codes, expansion budgets), and the overflow matrix includes 600x960, 1024x768 and 800x360.

### 8.4 Screen readers

The 190 `Semantics`/tooltip sites read ARB keys (audit in W7). Content names shown in a language other than the UI language (item names in `contentLocale` != app language) are wrapped in `Semantics(localeForSubtree: contentLocale)` (G15) so TalkBack/VoiceOver pronounce them correctly. Language changes are announced (6.5). Every icon-only button has a tooltip/semantic label key.

### 8.5 Reduced motion and color-blind safety

Reduced motion: 0 `disableAnimations` uses today; any animation added or touched by i18n work (language-switch, list cross-fade) checks `MediaQuery.disableAnimationsOf`. Color-blind safety is owned by the theme work; the i18n hook is that state (owned/locked/discount/rank) always has a text label key, never color only. Both are listed as W7 checks.

## 9. valorant-api language and content cache

- `AppLocale.tag` is the `language=` value (case-sensitive, `docs/research/content-api.md:65`); no mapping table. `ContentDb.empty/parse`, `ContentRepository.load` defaults and `contentProvider` read `contentLocaleProvider` (= `settings.contentLocale` or, when `"app"`, the app locale) instead of the literal `'vi-VN'`.
- `ContentRepository` already keys its cache per language (`<appSupport>/content/<language>/`, `cacheKey = manifestId|language|schema`, 23 endpoints), so 18 languages work with no schema change. Add `pruneLanguages(keep)` after a successful download: keep the current language and, if present, `en-US` (each language is about 1 MB gzip; weapons alone 3.65 MB unpacked). If the requested language has no cache and the download fails, fall back to a cached `en-US` pack.
- `ContentDb.parse` runs in `Isolate.run` and must stay locale-neutral (P-C). A regression test parses twice under different app locales and asserts identical objects, and that labels resolved through `content_labels.dart` differ (12.2).
- `ItemLanguage {vi,en}` migration: legacy JSON `itemLanguage: 'vi'` -> `contentLocale = "app"` (equals `vi` for pinned users), `'en'` -> `en-US`. The settings row "Tên vật phẩm" becomes "Item names: follow app language / any of 18".
- Official labels policy (P-C): roles, queues, tiers, currencies, weapon categories, ceremonies prefer the API text when its language equals the UI language and the UI is not `vi`; otherwise ARB. Some fields stay English in every API language (agent/map names, most bundle names): expected, not a bug.

## 10. Background isolate and notifications

Problem: the WorkManager isolate has no Riverpod, no widgets, no static state from the UI isolate, and `PlatformDispatcher.locales` in a headless engine is **unverified**; the design does not depend on it.

- **Handoff.** The UI isolate writes `settings.effectiveLocale` (6.2) whenever the effective locale/format/24 h changes (`ref.listen` in `ValVnApp.initState`). `BackgroundContext._create` reorders to `Prefs.create()` first, then reads the handoff (fallback: `settings.appLocale` tag, then `en` if shipped else `vi`), calls `initIntl(formatTag)` (`initializeDateFormatting()` for all locales, `Intl.defaultLocale`), and exposes `ctx.l10n = lookupAppLocalizations(locale)` and `ctx.formats`. Because `instance()` memoizes per isolate, `BackgroundContext.syncLocale()` (`await prefs.reload()` then rebuild `l10n`/`formats`) runs at the start of every task from `callbackDispatcher` and from `BackgroundWishlistCheckEnv.reload()`. A `debug` assert fires if code reads `ctx.l10n` before `syncLocale`.
- **Consumers.** `wishlist_alerts`, `wishlist_check`, `session_keep_alive`, `store_reset_reminder`, `lfg_poster_sync` take `ctx.l10n`/`ctx.formats` (`NotificationChannel` use sites: `session_keep_alive.dart:50`, `lfg_poster_sync.dart:155`, `store_reset_reminder.dart:86`, `wishlist_check.dart:244/282/330`).
- **Channels.** `NotificationChannel` becomes `id` + `String Function(AppLocalizations) name/description`. `flutter_local_notifications 22.3.1` re-creates the channel with the new name/description on every show/schedule; `NotificationService.refreshChannels(l10n)` recreates all four on a language change and `init` takes an `AppLocalizations`.
- **Baked/scheduled text.** The store reset reminder bakes title/body at scheduling time; on a locale change the controller re-runs `scheduleStoreResetReminder` for the active account. Wishlist/Night Market/session-expired texts are composed at fire time in the background isolate: nothing to reschedule. iOS background runs are best-effort, so the language may lag until the next open.
- **Time zone.** The fallback `Asia/Ho_Chi_Minh` in `notification_service.dart` becomes `UTC` with a log (owner confirms, 18.3).
- **Tests.** Round trip: write effective locale, build `BackgroundContext` with a fake `Prefs`, assert the notification title/body language; switch locale, `syncLocale`, assert again.

## 14. Translation pipeline

### 14.1 Source of truth and order

`app_vi.arb` with `@key` metadata is the source. Order: (1) vi -> English by the runner, owner-reviewed, because `en` is both the pivot and the runtime fallback; (2) the other 16 locales translated from vi + en together (vi alone lacks plural/pronoun/classifier context). `es_MX` is a delta over `es`: only keys that differ are translated; `zh_Hant` is translated in full.

### 14.2 Runner (`tool/l10n_translate.dart`)

A small Dart runner (or one Claude Code subagent per locale calling it) using the Messages API with a **forced tool call** whose `input_schema` is `[{key, text, note?}]` (parsing never depends on prose). Model is configurable (`L10N_MODEL`; default the current Sonnet-class model, an Opus-class model for legal documents and T0 keys). `arb_translate` is not used. Pseudo-code:

```text
for locale in targets:
  stale = keys where status[locale][key].h != hash(vi text + placeholders + description) or missing   // sourceHash
  for batch in chunk(groupBy(stale, prefix), 40..60):                 // same section keeps terminology consistent
    prompt = system(style guide of locale + glossary excerpt + rules) +
             items[{key, vi, en, description, placeholders(types, examples), pluralCategoriesRequired(locale),
                    maxLength, x-context, neighbours}]                // locked keys are NOT sent
    out = call(model, forcedTool)
    for item in out: errs = l10n_check.fast(item); retry with the concrete error text (max 2), else queue for a human
  write ARB canonical; status[locale][key] = {state: machine, h: hash}
```
Cost: about 1,190 keys x 17 locales = about 20,000 units, roughly 6k source words per locale, a few hundred thousand tokens per locale including metadata and retries; later edits touch only stale keys.

### 14.3 Glossary (`tool/l10n/glossary.yaml`, three layers)

(a) Locked tokens identical in every locale: `VP KC RP RR K/D/A ACS HS% ADR MVP PC Riot ID Riot Games VALORANT ValVN Premier PlayStation Xbox`, symbols and numerals. (b) Official game terminology harvested per locale from valorant-api in that locale's `apiCode` (`tool/l10n_glossary.dart`: currencies, contenttiers, competitivetiers, gamemodes/queues, agent roles, weapon categories, ceremonies) into `glossary.generated/<locale>.json`; the model MUST use these (Night Market, Radianite, Select/Deluxe/Premium/Exclusive/Ultra, Swiftplay, Spike Rush, Deathmatch, Controller/Duelist/Initiator/Sentinel, rank names). CLAUDE.md's "keep VP, RR, K/D/A, ACS, HS%, Battle Pass, skin, bundle, wishlist in English" applies to `vi` and to Latin-script locales by default; for ja/ko/zh/th/ar/ru these terms come from the game client's own vocabulary where the API or patch notes provide it, else are marked for native review. (c) Style guide per locale `tool/l10n/style/<locale>.md`: formality and second-person form, punctuation, gender-neutral phrasing, ar = Modern Standard Arabic, es = European, es_MX = Latin American, pt = Brazilian only, zh vs zh_Hant vocabulary, ja/ko/th honorific level. These are owner decisions (18.3), not assumed.

### 14.4 Harvesting and seeding

The same harvest fills `content_labels.dart` fallbacks (queue names, roles, tiers, currencies) so game terminology equals the client's without AI.

### 14.5 Legal documents

Same runner with document-level batches by section; validator checks section count and heading parity, paragraph-count parity (no dropped clause), defined terms, URLs/emails/version/date preserved, length ratio window. Output lands in `assets/legal/<locale>/`; every non-vi/en locale carries the machine-translation banner until counsel signs off (about 8.1k words x 17 = about 138k words). Priority native/legal review: de, fr, es, it, pl, pt (GDPR/LGPD markets).

### 14.6 Deterministic validation (`tool/l10n_check.dart`, blocking in CI; `flutter gen-l10n` is the final syntax check)

For every locale file and key:
1. same key set as the template (`es_MX` may be a subset), no extras; 2. same placeholder names and, where declared, types; ICU braces balanced (own recursive parser); no literal `{`/`}`; 3. plural has `other`, every category REQUIRED for the locale (4.4), every branch that shows a number keeps `{n}`; select has `other`; 4. locked/glossary tokens present exactly (`VP`, `RR`, `K/D/A`, `HS%`, `ACS`, `ValVN`, `Riot ID`, digits and separators such as the `/` in `{a}/{b}`); 5. not-copied: a non-vi locale contains no Vietnamese-only letters, a non-Latin locale contains at least one character of its script for any non-locked message longer than 3 characters, a message identical to vi or en is flagged unless locked or on `allowlist.yaml`; 6. length budget: `len <= x-max-length`, default `max(12, vi_len x factor)` with factors de 1.5, ru 1.4, fr/es/it/pt/pl/tr/id 1.35, en 1.3, th/ar 1.2, ja/ko/zh 0.9, hard caps for tabs/chips/buttons 14, badges 10, notification titles 40 (`budgets.yaml`); 7. whitespace parity (leading/trailing spaces, newline count, trailing ellipsis character), no introduced HTML/markdown/URLs except declared `x-tags`; 8. bidi: no stray direction marks in `ar`; 9. term consistency: for each glossary concept in the vi source the locale's official term occurs (warning); 10. profanity/brand-safety list on community strings (warning); 11. pseudo-locales, `AppLocale.values` and `kShippedLocales` consistency; 12. shipped locales have zero `en-fallback` keys. Failures go back to the model with the concrete error (max 2 retries), then to the human queue.

### 14.7 Quality gates beyond syntax and review tiers

Back-translation: each target is translated back to English by a second call and compared to the `en` source by a similarity judge; the lowest 5% per locale plus every plural or glossary-term message go to the review queue. Plural spot checks render sample numbers per locale (12.2). Overflow tests exercise the real translated text at 200% scale. **T0** keys (notifications, errors, tab/navigation labels, store and purchase-adjacent copy, consent/legal lead-ins, about 180 keys) must be `reviewed` by a native reader before a locale is marked shipped; **T1** (the rest) may ship machine-translated behind the Beta badge.

### 14.8 Status, sync and completeness

`lib/l10n/status/<locale>.json`: per key `{state: machine|reviewed|locked|en-fallback|stale, h}` (one file per locale so 17 agents never conflict). `tool/l10n_sync.dart`: creates any missing key in each non-template locale from `en` with `en-fallback` (so gen-l10n's template fallback to Vietnamese is never reached), copies locked keys from vi, marks changed sources `stale` (keeps the old translation), deletes removed keys, skips `es_MX` keys that `es` already has (inheritance), fills `zh_Hant` fully. CI fails if `build/l10n_untranslated.json` lists messages for a shipped locale, if a shipped locale has any `en-fallback` key, or if a key exists in vi but not in en. Editorial changes to a vi string use the normal edit: the hash change makes every locale `stale` until retranslated.

### 14.9 Not translated by AI

Country names (CLDR), native language names (const), weekday/month/number/date names (intl), content names (valorant-api), iOS `InfoPlist.strings` and Android label (generated from ARB by `l10n_platform`).

### 14.10 Shipping a locale

A locale enters `kShippedLocales` only when: `l10n_check` clean, zero `en-fallback`, T0 `reviewed`, overflow/RTL tests green, on-device font check done (script locales), legal banner present, consent-line language counsel-approved. `kShippedLocales` is mirrored in `status` metadata and asserted by a test.
