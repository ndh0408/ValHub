- Risk means the regression risk of applying the fix.

## 1. Executive summary

The Riot/account core is carefully built. I found no cross-account data leak in the PUUID-keyed provider families (one viewer-keying flaw on match details, AR-015), and no token, cookie or PUUID logging or egress beyond the one documented call to the community server.

The main problems are:

1. **Traffic shaping toward Riot's most fragile hosts (AR-001, AR-005, AR-006).**
   - Re-auth has no cooldown and retries immediately, even after a 429 or Cloudflare block.
   - The auth hosts sit outside the rate limiter.
   - Inline retries multiply with the Riverpod provider-level retry. That gives about 30 s of skeleton when offline and about 6.5 min on a hanging link.
2. **Sign-out is incomplete and not atomic (AR-002, AR-003, AR-014, AR-016, AR-018).**
   - RR history, loadout presets, a global name cache and the match cache survive sign-out.
   - The confirm dialog and the privacy policy say only the wishlist is kept.
   - A crash or kill mid-`remove()` orphans secrets. In-flight fetches can also re-create per-account files after the wipe.
3. **Secrets and config policy (AR-004, AR-009, AR-010, AR-011).**
   - The login note stores a plaintext Riot password. It has no device-auth gate and the clipboard copy is never cleared.
   - The token destination can be changed by remote config (latent today, because `remoteConfigUrl` is empty).
   - The remote-config safety net documented in SUMMARY §13 is not operational.
   - The client version from a third-party API is persisted unvalidated for 6 h.
4. **Reliability of headline background features (AR-007, AR-008).**
   - The store-reset reminder is one-shot.
   - Background transient failures trigger WorkManager retry storms, and there is no hard per-account time budget.
5. **Content cache (AR-012).** The first render blocks on a full re-download after each game patch, and the freshness marker is all-or-nothing.
6. **"No AI features".** The only ML feature is on-device ML Kit translation (AR-033). That is an owner decision.

There are 2 High, 12 Medium, 18 Low and 2 Info findings.

## 3. Verified correct — do not break

Each item is confirmed in code. Test names are given where they exist.

1. **Secret scoping and wipe.**
   - All Keychain/Keystore keys are `acct.<puuid>.*`, and `SecureKeys.allFor` includes the login note and the community session (`secure_store.dart:5-30`).
   - The wipe happens twice: under the account lock in `SessionManager.forget` (`session_manager.dart:188-214`), and again in `wipeAccountData` (`account_repository.dart:103-110`).
   - Covered by `account_providers_test.dart:184-217` and `session_manager_test.dart:303-338`.
2. **Sign-out ordering.**
   - Metadata is removed first, so a running re-auth (here or in the background isolate) cannot resurrect the account (`account_providers.dart:111-133`).
   - `_stillExists` reads the account list from disk and is checked before persisting cookies and tokens (`session_manager.dart:296-297,342-345,416-420`).
3. **Cross-isolate lock.**
   - It has a 15 s heartbeat, a 40 s stale takeover, and a waiter that never runs the body on timeout (`account_lock.dart:46-125`).
   - Single-flight per account (`session_manager.dart:282-292`; `session_manager_test.dart:137`).
4. **Cookie and token lifecycle.**
   - Rotated cookies are persisted before the new tokens are used, and the previous jar is kept (`session_manager.dart:340-354`).
   - The retry-outcome table is in `resolveReauthRetry` (`:44-62`).
   - Refresh happens 5 min before expiry (`riot_session.dart:40-41`).
   - `expiresAt` is computed on the device clock (`auth_callback.dart:117-138`).
   - Another isolate's fresh tokens are reused without a re-auth (`session_manager.dart:308-315`).
5. **needsLogin classification.** Only `login_required`, `interaction_required`, `consent_required` and `account_selection_required` (plus login redirects and `type` auth/multifactor) mark a session dead. Everything else is transient (`reauth_client.dart:65-120,129-205`). A post-re-auth failure re-checks the region once and then marks needsLogin, so there is no request loop (`session_manager.dart:224-270`).
6. **Auth interceptor.** It makes a single retry per request after 401 / 400 BAD_CLAIMS (guarded by `authRetried`). It has the name-service 403-JSON rule with a per-token memo, and never treats HTML 403 or SCHEDULED_DOWNTIME as an auth failure (`dio_factory.dart:97-210`; `error_classifier.dart:66-103`).
7. **PvpApi contract.** It throws only `RiotException` subtypes. Mutations are never retried. GETs get two quick retries. 429 sets a per-host cooldown honouring `Retry-After`. Bursts are capped at 8, 2/s, 3 in flight (`pvp_api.dart:492-567`; `rate_limiter.dart`).
8. **Error handling of odd bodies.** HTML detection is by content-type or body prefix (`error_classifier.dart:41-53`). The 403-HTML check precedes auth classification (`:133-139`). JSON parsing is defensive, with guarded casts only.
9. **Login WebView.**
   - Callback validation covers the strict path regex, single tokens, `state` and `nonce`, and `sub == expectedPuuid` on re-login (`auth_callback.dart:47-66,208-243`).
   - Cookies are cleared before and after capture (`login_screen.dart:85-92,180-208`).
   - Main-frame navigation is host-allowlisted; there are no JS bridges or file-access overrides.
   - There are no `badCertificateCallback` overrides and no `http://` endpoints in `lib/`.
10. **Secrets hygiene in logs.**
    - `SessionLog` scrubs UUIDs, JWTs, secret key-values, 32+ character strings and Riot IDs, and reduces URIs to templates with a query allowlist (`session_log.dart:214-273`).
    - `toString` is redacted on `RiotSession`, `AuthTokens`, `RiotCookieJar`, `LoginNote` and `Account`.
    - The only debug output is `debugPrint(runtimeType)`. There is no `LogInterceptor`, and the auth Dios are not logged at all.
    - The community API never sends a PUUID (only the token flow of item 11).
11. **Community egress gate.**
    - The Riot access token leaves the device only after per-account consent, under a rebuild-safe epoch check (`community_auth.dart:57-67,140-188`).
    - Consent is stored under `acct.<puuid>.community.consent` and re-read when the account disappears (`consent_providers.dart:20-64`).
    - Public reads stay anonymous (`community_api.dart:615-641`).
12. **Provider isolation.**
    - All data providers are families keyed by PUUID and watch `needsLogin` for refetch (`storefront.dart:731-761`, wallet, entitlements, loadout, battle pass, live game, account activity, community feed/LFG).
    - `xmppServiceProvider` is recreated on account switch and the old service is disposed (`xmpp_providers.dart:68-114`).
    - The live game controller is per PUUID and pauses in the background (`live_game_providers.dart:46-143,217-239`).
    - Live-game mutations use the widget's own `puuid`.
    - The store reminder is scheduled per account (`store_reset_reminder_host.dart:43-90`).
13. **Offline caches.** They are written under `cache/acct/<puuid>/` through one helper (`economy_fetch.dart:121`; `json_file_cache.dart:40`). Sanitised path segments, an atomic tmp+rename write, and `deletePrefix` on the account directory all work as intended.
14. **Background isolate.**
    - Each account is handled with its own session, independent of the active account (`wishlist_check.dart:185-197`; `session_keep_alive.dart:30-64`).
    - The account list is read and written from disk (`account_repository.dart:34-41`), and `Prefs.reload` swaps the cache atomically (`prefs.dart:68-88`).
    - Notification-id tracking is read from disk (`notification_service.dart:297-312`).
    - The wishlist check is once per UTC day, with the notified-map dedupe.
15. **Platform hardening.**
    - Android backup is fully off (`allowBackup=false`, `data_extraction_rules.xml` excludes cloud and device-transfer).
    - `INTERNET`, `POST_NOTIFICATIONS` and `RECEIVE_BOOT_COMPLETED` are declared, the boot receivers are present, and exact-alarm permissions are removed (`AndroidManifest.xml:5-12,41-52`).
    - iOS Keychain accessibility is `first_unlock_this_device` (`secure_store.dart:54-57`).
    - The keychain is wiped after a reinstall (`main.dart:57-65`).
    - iOS `BGTaskSchedulerPermittedIdentifiers` matches the AppDelegate and Dart constant.
16. **Deep links.**
    - Payloads are local, app-generated route locations.
    - There are no URL schemes, App Links, associated domains or intent filters beyond MAIN. The app has no externally triggerable navigation surface.
    - `parseDeepLink` drops scheme and host and lowercases the account (`deep_links.dart:44-62`).
    - A per-tap nonce re-triggers same-link taps.
    - Hosted pages (`/battlepass`, `/settings`) open with Back working (`deep_links.dart:95-117`).
    - Redirect rules cover the no-account case and `/welcome`→`/home` (`router.dart:35-42`; `router_test.dart`).
17. **Notifications.**
    - Timing uses absolute instants (device time zone only affects display).
    - Turning a toggle off cancels already-scheduled reminders for every account (`settings_providers.dart:114-138`).
    - Per-account tracking plus `cancelForAccount` remove pending and delivered notifications (`notification_service.dart:297-320`).
18. **Per-account wishlist setting.** `wishlistNotificationsByAccount[id]` is removed on `remove()` (`account_providers.dart:121-127`), with a one-time migration that starts new accounts opted out (`app_settings.dart:186-213`).

## Appendix B — cold-start request timeline (active account A)

1. `main()` runs serially: locale, tz, prefs, keychain marker, migrations, remote config (bundled asset), session log, notification init. It then fires `initBackgroundWork` without awaiting and calls `runApp` (AR-028).
2. `ValVnApp.initState` starts `/v1/version` (gated to 6 h).
3. The shell mounts two hosts.
   - `LiveGameOverlayHost` starts `liveGameProvider(A)`.
   - `StoreResetReminderHost` starts `storefrontProvider(A)`.
   - Both need `session(A)`. With a stored valid token that costs 0 network calls. With an expired token it costs 2–3 sequential calls (authorize GET, POST fallback, entitlements) before any PD/GLZ call.
4. Home cards then run in parallel behind the PD limiter (3 concurrent, 2/s): wallet, MMR, competitive updates page 1, contracts, premium entitlement, daily ticket, status JSON per region, and the community previews (only with consent). Other-account cards each fetch G-1 and may trigger their own re-auth (AR-001).
5. Content runs in parallel: `/version` (≤5 s), 23 file reads, `Isolate.run` parse. Home store, rank and battle-pass cards wait on it (skeleton), and on patch day it blocks on the network (AR-012).
