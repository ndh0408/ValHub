# VanHub — runtime locale wiring, 02/10/2026

This follows the [final gap audit](FINAL_GAP_AUDIT_2026-10-02.md), preserving the
existing localization system, account/storage identifiers and shipped-locale
filter. **This is a partial W5 checkpoint, not completion of W2–W7 or a release
acceptance.** No translations, paid AI/API or new localization system were added.

## Gap found before implementation

| Existing area | Gap | Resolution in this checkpoint |
|---|---|---|
| Locale providers / `L10nBootstrap` | Root still passed fixed `appLocale` | `MaterialApp` watches `appLocaleProvider`, with only `kShippedLocales` eligible |
| `AppFormats` / `formatsProvider` | Root did not install the scope | Scope above the router app also reaches dialog routes |
| `EffectiveLocale` handoff | Reader/provider existed, but no UI writer | Initial and subsequent snapshots are persisted in order; failed writes are logged without preference contents and the queue continues |
| Existing item-name preference | Snapshot defaulted to the UI locale and lost the separate English item-name choice | Provider preserves `AppSettings.itemLanguage.apiCode`; no preference migration/removal |

The snapshot writer captures its dependencies before asynchronous work; it does
not read a disposed widget ref. Updating the snapshot does not overwrite
`settings.appLocale` or change the existing upgrade pin. Locale changes initialize
the existing `intl` data. Existing themes, notifications, warmup and deep links
remain in the root widget.
